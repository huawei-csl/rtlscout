# Prove a candidate for a Lean-gated slot

A Lean-gated slot's oracle is a kernel-checked proof that your design equals the golden:
`Spec.Correct D<hash>_Circuit.eval` (combinational: equal on every input) or
`Spec.Correct D<hash>_Circuit.machine` (clocked: equal output trace on every input sequence).
The gate translates your netlist to `D<hash>_Circuit.lean` itself; you supply only the proof.

## Workflow

1. Write `work/design.py` (`build() -> Component/Netlist`), then get the workspace:
   ```
   spire db verify work/design.py --slot <slot> --workspace work/ws
   ```
   Without a proof this exits 2 **on purpose** and prints the file to write, e.g.
   `write D97a95c77dc_Proof.lean with theorem implements : Spec.Correct D97a95c77dc_Circuit.eval`.
   `work/ws/` now holds: `SpireSemantics.lean`, `Interface.lean`, `GoldenCircuit.lean`, `Spec.lean`,
   every spec layer (`Mmac.lean`, `MmacProof.lean`, …), every admitted design's
   `D…_Circuit.lean`/`D…_Proof.lean`, and your `D<hash>_Circuit.lean`. Read the circuit file —
   it is what you are proving about.
2. Write `work/ws/D<hash>_Proof.lean`: `import D<hash>_Circuit`, `import Spec`, what else you
   use, `namespace D<hash>_Proof`, your lemmas, and last `theorem implements : <statement>`
   with the statement copied verbatim from step 1.
3. `cd work/ws && lake build` — iterate on the first Lean error. Only the proof file is yours;
   the other files are regenerated by the gate.
4. `spire db insert work/design.py --slot <slot> --proof work/ws/D<hash>_Proof.lean --source <your tag>`

## Proof shapes (pick the cheapest that fits)

**Through a spec layer** — a layer `L` provides `L.equiv : ∀ e, L.Correct e ↔ Spec.Correct e`,
usually an integer-level statement. Prove the integer statement, convert:
```lean
theorem implements : Spec.Correct D_aCircuit.eval :=
  (Mmac.equiv _).mp (by intro i; and_intros <;> (simp [D_aCircuit.eval]; ac_rfl))
```
`simp` needs one `@[simp]` exactness lemma per arithmetic shape in your netlist
(`(addSS 17 a b).toInt = a.toInt + b.toInt`, proven with `bv_decide` on the overflow flag) —
copy the pattern from an admitted design's proof.

**Delta to an admitted design** `b` that differs from yours by a local rewrite:
```lean
theorem step (i : Inputs) : D_aCircuit.eval i = D_bCircuit.eval i := by
  simp only [D_aCircuit.eval, D_bCircuit.eval, mulSS, BitVec.mul_comm]
theorem implements : Spec.Correct D_aCircuit.eval := fun i => (step i).trans (D_bProof.implements i)
```

**Whole-design SAT** — small bitwise/control logic:
```lean
theorem implements : Spec.Correct D_aCircuit.eval := by
  intro i; apply Outputs.ext <;> (simp only [D_aCircuit.eval, GoldenCircuit.eval]; spire_unfold; bv_decide)
```

**Clocked slot** — a simulation relation `R (t : D.State) (s : GoldenCircuit.State)` and three lemmas
(init, step, output), each closed by `spire_unfold; bv_decide`, then
`Machine.trace_eq_of_rel D.machine GoldenCircuit.machine R h0 hstep hout`. `R` is state equality
when your registers are the golden's; otherwise say how yours encode the golden's
(e.g. `t.hi ++ t.lo = s.acc`). A design with a different latency is not trace-equivalent and cannot
be admitted to this slot.

## Rules enforced by the gate

- The final theorem keeps the exact statement; the gate type-checks it against `Spec`.
- No `sorry`, no `axiom`. `bv_decide` is fine anywhere (its certificates are audited by type).
- Rejections: `ProofFailed` (does not build; the Lean log is returned), `ProofRejected` (statement
  weakened or bad axiom). Fix your design or your proof — never the frozen files.
- Provenance: `--source` must be your honest role tag.
